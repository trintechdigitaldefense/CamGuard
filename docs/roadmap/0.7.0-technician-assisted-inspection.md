# CamGuard 0.7.0 — Technician-Assisted CCTV Security Inspection

## Status

**Milestone:** 0.7.0  
**Implementation status:** Initial data model, checklist templates, evidence-reference validation, standalone JSON export, assessment-level JSON/Markdown/PDF report integration and technician CLI workflow are implemented on a development branch. Full regression and security validation remain outstanding. This is not part of the published 0.5.0rc1 release.

## Objective

Extend network observations with documented, technician-confirmed checks for controls that cannot be safely or reliably inferred from unauthenticated network probes.

## Six checklist areas

1. **Account permissions:** unique accounts, least privilege, restricted administrators, removal of former users and MFA availability.
2. **Default-credential policy:** commissioning defaults changed, unique device secrets, password policy, lockout/rate limiting and secure secret handling.
3. **NVR configuration:** firmware support, minimized services, restricted management, time synchronization and protected configuration backups.
4. **Remote access:** approved access method, unnecessary port forwarding, VPN/equivalent controls, third-party access governance and logging.
5. **Physical security:** camera tamper resistance, secured recorder/network equipment, cable protection, power protection and physical access controls.
6. **Recording retention:** approved retention period, storage health, recording continuity, recovery and privacy controls.

Each item supports pass, fail, not_verified, not_applicable and needs_attention. Pass and Fail require an evidence reference. Not Applicable and Needs Attention require explanatory notes. An unanswered item remains unanswered; it is never silently treated as Pass.

## Data and evidence handling

- Every inspection is versioned and linked to an assessment, inventory asset, device IP, inspector and timestamp.
- Evidence is represented by operator-managed references, not embedded files or raw footage.
- Do not record passwords, tokens, cookies, private keys, authentication headers or other secrets.
- Notes are length-limited and basic secret-like patterns are rejected; this is a guardrail, not a guarantee that free text is safe.
- Technician statements are explicitly identified as supplied observations, not independently verified by CamGuard.
- Keep inspection status separate from CVE/KEV applicability and existing vulnerability risk scores.

## Safety boundaries

This is a manual workflow. CamGuard does not log in to devices, attempt default passwords, enumerate user accounts, change configurations, retrieve recordings, inspect live video or access private administrative APIs. Any direct inspection is performed by an authorized technician under the client's approval and procedures.

- [ ] Full regression and security tests, including report escaping and malformed input.
- [x] Documentation and command examples for technicians and clients.

## JSON shape

An inspection contains schema_version, inspection_id, assessment_id, asset_id, device_ip, inspector, inspected_at, checklist_version, responses and limitations. Each response records category/check identifiers, the question, status, notes, evidence references and review timestamp.

The standalone JSON writer validates an inspection before writing it. Assessment-level report writers also serialize an optional inspections collection; each attached inspection is validated before Markdown and PDF rendering.
